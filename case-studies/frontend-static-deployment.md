# 프런트엔드 정적 배포

## 상태

공개 전환 후보로 선별한 주제입니다. 일반화된 React SPA를 대상으로 빌드, 업로드, 캐시, 되돌리기를 재현한 뒤 탐색 메뉴에 연결할 예정입니다.

## 다룰 질문

- 정적 자산과 `index.html`을 어떤 순서로 배포하는가?
- SPA 화면 경로와 실제 파일 누락을 어떻게 구분하는가?
- 이전 릴리스의 해시 자산을 언제 삭제하는가?
- 배포 실패를 어떻게 감지하고 되돌리는가?

## 공개 작성 기준

- 실제 도메인과 클라우드 자원 이름은 사용하지 않습니다.
- 캐시 헤더와 화면 경로 검증을 실행 가능한 예제로 만듭니다.
- [React·Vite 정적 파일을 S3와 CloudFront로 제공하기](../architecture/frontend-serving/react-vite-s3-cloudfront.md)와 중복되는 개념 설명은 링크로 대체합니다.
