# 문서 작성 정책

## 핵심 원칙

공개 문서는 내부 문서의 익명화 버전이 아닙니다. 경험에서 질문과 설계 기준만 추출하고, 기술적으로 독립된 글로 새로 작성합니다.

## 포함하지 않는 정보

| 유형 | 처리 방법 |
|---|---|
| 회사·고객·서비스·프로젝트 식별자 | 역할 중심의 일반 표현으로 변경 |
| 실제 도메인·저장소·클라우드 자원 이름 | 제거하거나 예약 예시 값으로 변경 |
| 계정·연락처·개인정보 | 제거 |
| 운영 데이터·실제 상품 정보 | 임의 데이터로 교체 |
| 내부 일정·계약·책임 관계 | 기술 의사결정에 필요한 상대적 흐름만 남김 |
| 내부 코드 | 같은 개념을 보이는 최소 예제로 재작성 |

## 일반화 예시

| 원본의 성격 | 공개 문서 표현 |
|---|---|
| 특정 조직의 레거시 서비스 | `기존 시스템` |
| 특정 신규 서비스 | `신규 커머스 플랫폼` |
| 운영 관리자 주소 | `admin.example.com` |
| 실제 상품 | `상품 A` |
| 실제 담당자의 실수 | 검증 절차와 시스템 안전장치의 부재 |

## 문서 구조

주제에 맞는 항목만 선택합니다.

1. 핵심 요약
2. 문제 상황
3. 개념과 동작 원리
4. 설계 대안
5. 선택 기준
6. 구현 예시
7. 장점과 단점
8. 운영 시 주의점
9. 정리
10. 참고자료

## 출처와 불확실성

- 버전에 따라 달라지는 내용은 버전 범위를 적습니다.
- 공식 문서를 우선 연결합니다.
- 측정하지 않은 성능 주장은 가설로 표현합니다.
- 예제는 설명을 위한 모델이며 모든 시스템의 정답으로 제시하지 않습니다.
